# Spec Delta

## Purpose

对候选人的每道主观题作答进行 AI 自动评分与评价：提交后由后台异步调用 OpenAI 兼容 API 完成评分并入库，不阻塞答题流程；全部题目评分完成后汇总总体分数与状态（优秀/合格/不合格）。

## ADDED Requirements

### Requirement: 每题提交触发异步评分
每道题答案提交成功后，系统 SHALL 在后台异步任务中调用 AI（携带题目、参考答案与候选人作答）生成 0-100 的整数评分与文字评价并保存到数据库；评分过程 MUST NOT 阻塞提交接口响应与前端答题流程。

#### Scenario: 提交后立即进入下一题
- **WHEN** 候选人提交某题答案
- **THEN** 提交接口立即返回成功，前端进入下一题；后台任务随后完成该题评分并入库

#### Scenario: 空答案评分
- **WHEN** 超时自动交卷导致某题以空答案提交
- **THEN** 系统直接记该题评分为 0、评价为"未作答"，不调用 AI

### Requirement: AI 服务可配置与失败重试
AI 调用 SHALL 通过环境变量配置 OpenAI 兼容 API 的 base_url、api_key 与 model；调用失败时系统 MUST 自动重试有限次数，最终失败的题目标记为"评分失败"且 MUST NOT 中断其他题目的评分。

#### Scenario: AI 调用临时失败后重试成功
- **WHEN** 某题评分调用首次失败、重试成功
- **THEN** 该题最终保存有效评分与评价

#### Scenario: 重试耗尽
- **WHEN** 某题评分重试次数耗尽仍失败
- **THEN** 该题标记为"评分失败"，其余题目评分不受影响，明细页对该题显示评分失败

### Requirement: 总体分数与状态计算
全部题目作答提交（交卷）且评分完成后，系统 SHALL 以各题评分的平均分（四舍五入取整）作为总体分数，并按阈值判定状态：≥85 为优秀，60-84 为合格，<60 为不合格；存在评分失败题目时 SHALL 仅按已成功评分题目计算并保留失败标记。交卷前考试状态 MUST 保持"未完成"。

#### Scenario: 优秀判定
- **WHEN** 一场考试全部题目评分完成且平均分为 90
- **THEN** 总体分数为 90，状态为"优秀"

#### Scenario: 合格与不合格边界
- **WHEN** 平均分分别为 60 与 59
- **THEN** 状态分别为"合格"与"不合格"

#### Scenario: 交卷后评分仍在进行
- **WHEN** 候选人已交卷但仍有题目在评分中
- **THEN** 考试完成时间已记录，总体分数与状态在全部评分结束后才最终确定，列表中在此之前显示评分进行中
